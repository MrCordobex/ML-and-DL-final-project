\section{Introducción al Problema}

\subsection{El Desafío Médico: Cáncer de Piel}

El cáncer de piel es uno de los tipos de cáncer más comunes a nivel mundial. Según la Organización Mundial de la Salud, cada año se diagnostican más de 3 millones de casos de cáncer de piel no melanoma y aproximadamente 132.000 casos de melanoma maligno. La detección temprana es \textbf{crítica}: un melanoma detectado en etapa temprana tiene una tasa de supervivencia superior al 95\%, mientras que en etapas avanzadas esta tasa cae drásticamente por debajo del 20\%.

\begin{warningbox}[Importancia Clínica del Melanoma]
El melanoma (MEL) representa solo el 1\% de los cánceres de piel, pero es responsable de la gran mayoría de muertes por cáncer de piel. Por esta razón, en nuestro trabajo \textbf{priorizamos la detección correcta de melanomas} sobre otras métricas generales.
\end{warningbox}

\subsection{¿Qué es la Dermatoscopia?}

La \textbf{dermatoscopia} (también llamada dermoscopia o microscopía de epiluminiscencia) es una técnica no invasiva que permite visualizar estructuras de la piel no visibles a simple vista. Utiliza un instrumento llamado \textit{dermatoscopio} que proporciona:

\begin{itemize}
    \item \textbf{Iluminación}: Luz polarizada o no polarizada
    \item \textbf{Magnificación}: Típicamente 10x
    \item \textbf{Eliminación de reflejos}: Mediante aceite de inmersión o polarización cruzada
\end{itemize}

Esto permite observar patrones como:
\begin{itemize}
    \item Redes de pigmento
    \item Glóbulos y puntos
    \item Velos azul-blanquecinos
    \item Estructuras vasculares
\end{itemize}

\section{Fundamentos Matemáticos de Redes Neuronales}

\subsection{El Perceptrón: La Neurona Artificial}

\subsubsection{Modelo Matemático}

Una neurona artificial (perceptrón) es la unidad básica de una red neuronal. Matemáticamente:

\begin{equation}
y = \sigma\left(\sum_{i=1}^{n} w_i x_i + b\right) = \sigma(\mathbf{w}^T \mathbf{x} + b)
\end{equation}

Donde:
\begin{itemize}
    \item $\mathbf{x} = [x_1, x_2, ..., x_n]^T$ es el vector de entradas
    \item $\mathbf{w} = [w_1, w_2, ..., w_n]^T$ es el vector de pesos (parámetros aprendibles)
    \item $b$ es el sesgo (bias)
    \item $\sigma$ es la función de activación
    \item $y$ es la salida
\end{itemize}

\subsubsection{Funciones de Activación}

Las funciones de activación introducen \textbf{no-linealidad} en la red. Sin ellas, una red profunda sería equivalente a una transformación lineal simple.

\begin{mathbox}[Funciones de Activación Comunes]
\textbf{Sigmoide:}
\begin{equation}
\sigma(x) = \frac{1}{1 + e^{-x}} \quad \text{Rango: } (0, 1)
\end{equation}

\textbf{Tanh (Tangente Hiperbólica):}
\begin{equation}
\tanh(x) = \frac{e^x - e^{-x}}{e^x + e^{-x}} \quad \text{Rango: } (-1, 1)
\end{equation}

\textbf{ReLU (Rectified Linear Unit):}
\begin{equation}
\text{ReLU}(x) = \max(0, x) = \begin{cases} x & \text{si } x > 0 \\ 0 & \text{si } x \leq 0 \end{cases}
\end{equation}
\end{mathbox}

\textbf{¿Por qué ReLU es la más usada?}
\begin{enumerate}
    \item \textbf{Computacionalmente simple}: Solo una comparación
    \item \textbf{No saturación positiva}: El gradiente no se desvanece para $x > 0$
    \item \textbf{Sparsity}: Muchas neuronas se ``apagan'' (salida 0), lo que actúa como regularización
\end{enumerate}

\subsection{Redes Multicapa (MLP)}

Un \textbf{Perceptrón Multicapa} (MLP) apila múltiples capas de neuronas:

\begin{align}
\mathbf{h}^{(1)} &= \sigma(\mathbf{W}^{(1)} \mathbf{x} + \mathbf{b}^{(1)}) \\
\mathbf{h}^{(2)} &= \sigma(\mathbf{W}^{(2)} \mathbf{h}^{(1)} + \mathbf{b}^{(2)}) \\
&\vdots \\
\mathbf{y} &= \text{softmax}(\mathbf{W}^{(L)} \mathbf{h}^{(L-1)} + \mathbf{b}^{(L)})
\end{align}

Donde $\mathbf{h}^{(l)}$ son las activaciones de la capa $l$, también llamadas \textit{hidden states} o características latentes.

\subsection{La Función Softmax}

Para clasificación multiclase, la capa final usa \textbf{softmax} para convertir los logits (valores crudos) en probabilidades:

\begin{equation}
\text{softmax}(z_i) = \frac{e^{z_i}}{\sum_{j=1}^{C} e^{z_j}} \quad \text{para } i = 1, ..., C
\end{equation}

\textbf{Propiedades:}
\begin{itemize}
    \item $\sum_{i=1}^{C} \text{softmax}(z_i) = 1$ (suman 1, como probabilidades)
    \item $\text{softmax}(z_i) > 0$ para todo $i$ (siempre positivas)
    \item Amplifica las diferencias: el valor más alto domina
\end{itemize}

\begin{lstlisting}[caption={Implementación de Softmax en PyTorch}]
import torch.nn.functional as F

# logits: tensor de forma [batch_size, num_classes]
logits = model(images)  # Salida cruda del modelo

# Convertir a probabilidades
probabilities = F.softmax(logits, dim=1)

# La clase predicha es la de mayor probabilidad
predictions = probabilities.argmax(dim=1)
\end{lstlisting}

\subsection{Función de Pérdida: Cross-Entropy}

\subsubsection{Definición Matemática}

La \textbf{Cross-Entropy} (Entropía Cruzada) mide la ``distancia'' entre la distribución predicha $\hat{y}$ y la distribución real $y$:

\begin{equation}
\mathcal{L}_{\text{CE}} = -\sum_{c=1}^{C} y_c \log(\hat{y}_c)
\end{equation}

Para clasificación con etiquetas ``hard'' (one-hot), donde $y_c = 1$ solo para la clase correcta $c^*$:

\begin{equation}
\mathcal{L}_{\text{CE}} = -\log(\hat{y}_{c^*})
\end{equation}

\begin{mathbox}[Intuición de Cross-Entropy]
\begin{itemize}
    \item Si $\hat{y}_{c^*} \approx 1$ (predicción perfecta): $\mathcal{L} \approx -\log(1) = 0$
    \item Si $\hat{y}_{c^*} \approx 0$ (predicción terrible): $\mathcal{L} \approx -\log(0) \rightarrow \infty$
\end{itemize}
La pérdida penaliza exponencialmente las predicciones incorrectas con alta confianza.
\end{mathbox}

\subsubsection{Cross-Entropy Ponderada}

Para datasets desbalanceados, ponderamos la pérdida de cada clase:

\begin{equation}
\mathcal{L}_{\text{weighted}} = -\sum_{c=1}^{C} w_c \cdot y_c \log(\hat{y}_c)
\end{equation}

Los pesos se calculan inversamente proporcionales a la frecuencia:

\begin{equation}
w_c = \frac{N}{C \cdot n_c}
\end{equation}

Donde $N$ es el total de muestras, $C$ el número de clases, y $n_c$ las muestras de la clase $c$.

\begin{lstlisting}[caption={Cálculo de pesos de clase en Python}]
import numpy as np
import torch

# Contar muestras por clase
labels = train_dataset.targets  # Lista de etiquetas
class_counts = np.bincount(labels)
# Ejemplo: [90, 85, 35, 95, 88, 92] (MEL tiene 35)

# Calcular pesos inversamente proporcionales
weights = 1.0 / class_counts
weights = weights / weights.sum() * len(class_counts)  # Normalizar
# Resultado: [0.75, 0.79, 2.25, 0.71, 0.76, 0.73]
# MEL (indice 2) tiene peso ~3x mayor

# Crear loss ponderada
class_weights = torch.FloatTensor(weights).to(device)
criterion = nn.CrossEntropyLoss(weight=class_weights)
\end{lstlisting}

\subsection{Backpropagation: El Algoritmo de Aprendizaje}

\subsubsection{El Problema de Optimización}

Entrenar una red neuronal es un problema de optimización:

\begin{equation}
\boldsymbol{\theta}^* = \arg\min_{\boldsymbol{\theta}} \frac{1}{N} \sum_{i=1}^{N} \mathcal{L}(f(\mathbf{x}_i; \boldsymbol{\theta}), y_i)
\end{equation}

Donde $\boldsymbol{\theta}$ representa todos los parámetros (pesos y biases) de la red.

\subsubsection{Descenso de Gradiente}

La optimización se realiza mediante \textbf{descenso de gradiente}:

\begin{equation}
\boldsymbol{\theta}_{t+1} = \boldsymbol{\theta}_t - \eta \nabla_{\boldsymbol{\theta}} \mathcal{L}
\end{equation}

Donde $\eta$ es el \textbf{learning rate} (tasa de aprendizaje).

\subsubsection{La Regla de la Cadena}

\textbf{Backpropagation} calcula eficientemente $\nabla_{\boldsymbol{\theta}} \mathcal{L}$ usando la regla de la cadena. Para una red de dos capas:

\begin{equation}
\frac{\partial \mathcal{L}}{\partial w^{(1)}_{ij}} = \frac{\partial \mathcal{L}}{\partial \hat{y}} \cdot \frac{\partial \hat{y}}{\partial h^{(2)}} \cdot \frac{\partial h^{(2)}}{\partial h^{(1)}} \cdot \frac{\partial h^{(1)}}{\partial w^{(1)}_{ij}}
\end{equation}

El gradiente ``fluye hacia atrás'' desde la pérdida hasta los parámetros.

\subsection{Optimizadores Modernos}

\subsubsection{SGD con Momentum}

El SGD básico puede oscilar en valles. El \textbf{momentum} añade ``inercia'':

\begin{align}
\mathbf{v}_t &= \gamma \mathbf{v}_{t-1} + \eta \nabla_{\boldsymbol{\theta}} \mathcal{L} \\
\boldsymbol{\theta}_{t+1} &= \boldsymbol{\theta}_t - \mathbf{v}_t
\end{align}

Donde $\gamma \approx 0.9$ es el coeficiente de momentum.

\subsubsection{Adam (Adaptive Moment Estimation)}

\textbf{Adam} combina momentum con learning rates adaptativos por parámetro:

\begin{align}
\mathbf{m}_t &= \beta_1 \mathbf{m}_{t-1} + (1-\beta_1) \nabla_{\boldsymbol{\theta}} \mathcal{L} \quad \text{(Primer momento)} \\
\mathbf{v}_t &= \beta_2 \mathbf{v}_{t-1} + (1-\beta_2) (\nabla_{\boldsymbol{\theta}} \mathcal{L})^2 \quad \text{(Segundo momento)} \\
\hat{\mathbf{m}}_t &= \frac{\mathbf{m}_t}{1-\beta_1^t} \quad \text{(Corrección de sesgo)} \\
\hat{\mathbf{v}}_t &= \frac{\mathbf{v}_t}{1-\beta_2^t} \\
\boldsymbol{\theta}_{t+1} &= \boldsymbol{\theta}_t - \frac{\eta}{\sqrt{\hat{\mathbf{v}}_t} + \epsilon} \hat{\mathbf{m}}_t
\end{align}

Valores típicos: $\beta_1 = 0.9$, $\beta_2 = 0.999$, $\epsilon = 10^{-8}$.

\subsubsection{AdamW: Weight Decay Correcto}

\textbf{AdamW} (Loshchilov \& Hutter, 2017) corrige un error sutil en la implementación original de Adam. En Adam clásico, el weight decay se aplicaba al gradiente adaptado, lo cual es matemáticamente incorrecto.

\begin{equation}
\boldsymbol{\theta}_{t+1} = \boldsymbol{\theta}_t - \eta \left( \frac{\hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t} + \epsilon} + \lambda \boldsymbol{\theta}_t \right)
\end{equation}

El término $\lambda \boldsymbol{\theta}_t$ es el weight decay aplicado \textbf{directamente} a los pesos.

\begin{lstlisting}[caption={Configuración de AdamW en PyTorch}]
import torch.optim as optim

optimizer = optim.AdamW(
    model.parameters(),
    lr=1e-3,           # Learning rate
    betas=(0.9, 0.999), # Coeficientes de momento
    eps=1e-8,          # Estabilidad numerica
    weight_decay=0.01  # Regularizacion L2
)
\end{lstlisting}

\section{Redes Neuronales Convolucionales (CNNs)}

\subsection{Motivación: ¿Por qué no MLPs para Imágenes?}

Consideremos una imagen de 224×224 píxeles en RGB:

\begin{itemize}
    \item \textbf{Dimensión de entrada}: $224 \times 224 \times 3 = 150.528$ valores
    \item \textbf{Primera capa densa de 1000 neuronas}: $150.528 \times 1000 = 150.528.000$ parámetros
    \item \textbf{Solo en la primera capa}: $>$150 millones de parámetros
\end{itemize}

Esto es:
\begin{enumerate}
    \item \textbf{Computacionalmente prohibitivo}
    \item \textbf{Propenso a overfitting} masivo
    \item \textbf{No explota la estructura espacial} de las imágenes
\end{enumerate}

\subsection{Los Principios de las Convoluciones}

\subsubsection{Conectividad Local}

En lugar de conectar cada píxel a cada neurona, cada neurona solo ``ve'' una región pequeña llamada \textbf{campo receptivo} (receptive field):

\subsubsection{Compartición de Pesos}

El mismo conjunto de pesos (el \textbf{kernel} o \textbf{filtro}) se aplica a todas las posiciones de la imagen:

\begin{equation}
\text{Parámetros de un kernel 3×3} = 3 \times 3 \times \text{canales\_entrada} + 1 = 28 \text{ (para RGB)}
\end{equation}

Comparado con los 150 millones de un MLP, ¡esto es una reducción de $>$5 millones de veces!

\subsubsection{Invarianza a Traslación}

Gracias a la compartición de pesos, si un filtro detecta un borde vertical en la esquina superior izquierda, también lo detectará en cualquier otra posición.

\subsection{La Operación de Convolución 2D}

\subsubsection{Definición Matemática}

La convolución discreta 2D entre una imagen $I$ y un kernel $K$ se define como:

\begin{equation}
(I * K)[i,j] = \sum_{m=-k}^{k} \sum_{n=-k}^{k} I[i+m, j+n] \cdot K[m,n]
\end{equation}

Para un kernel de tamaño $(2k+1) \times (2k+1)$.

\subsubsection{Parámetros de la Convolución}

\begin{table}[H]
\centering

\begin{tabular}{@{}llp{6cm}@{}}
\toprule
\textbf{Parámetro} & \textbf{Símbolo} & \textbf{Efecto} \\
\midrule

\textbf{Fórmula del tamaño de salida:}
\begin{equation}
\text{output\_size} = \left\lfloor \frac{\text{input\_size} + 2p - k}{s} \right\rfloor + 1
\end{equation}

    in_channels=3,      # RGB
    out_channels=64,    # 64 filtros diferentes
    kernel_size=3,      # Kernel 3x3
    stride=1,           # Paso de 1 pixel
    padding=1           # Mantiene el tamano espacial
)

# Para entrada [batch, 3, 224, 224]
# Salida: [batch, 64, 224, 224]
\end{lstlisting}

\subsection{Capas de Pooling}

El \textbf{pooling} reduce la dimensionalidad espacial, proporcionando:
\begin{itemize}
    \item Invarianza a pequeñas traslaciones
    \item Reducción de parámetros en capas posteriores
    \item Mayor campo receptivo efectivo
\end{itemize}

\subsubsection{Max Pooling}

Toma el valor máximo en cada ventana:

\begin{equation}
\text{MaxPool}_{k \times k}(I)[i,j] = \max_{m,n \in [0,k)} I[i \cdot s + m, j \cdot s + n]
\end{equation}

\subsection{Batch Normalization}

\textbf{Batch Normalization} (Ioffe \& Szegedy, 2015) normaliza las activaciones de cada capa:

\begin{equation}
\hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}}
\end{equation}

Seguido de una transformación aprendible:
\begin{equation}
y_i = \gamma \hat{x}_i + \beta
\end{equation}

Donde $\mu_B$ y $\sigma_B^2$ son la media y varianza del mini-batch, y $\gamma$, $\beta$ son parámetros aprendibles.

\textbf{Beneficios:}
\begin{itemize}
    \item Permite learning rates más altos
    \item Reduce la dependencia de la inicialización
    \item Actúa como regularizador (debido a la variabilidad entre batches)
\end{itemize}

\section{Arquitecturas: ResNet y DenseNet}

\subsection{ResNet: Redes Residuales}

\subsubsection{El Problema de la Degradación}

Antes de ResNet (2015), entrenar redes muy profundas ($>$20 capas) era problemático. Sorprendentemente, añadir más capas \textbf{empeoraba} el rendimiento incluso en el conjunto de \textbf{entrenamiento}:

\caption{Problema de degradación: una red de 56 capas tiene \textbf{peor} error que una de 20 capas.}

Esto \textbf{no es overfitting} (el error de train también es peor). Es un problema de \textbf{optimización}: los gradientes se desvanecen o explotan en redes profundas.

\subsubsection{La Solución: Bloques Residuales}

La idea clave de He et al. es: si una capa adicional no ayuda, al menos debería poder aprender la \textbf{función identidad} (no hacer nada).

En lugar de aprender $H(x)$ directamente, la red aprende el \textbf{residuo}:
\begin{equation}
F(x) = H(x) - x \implies H(x) = F(x) + x
\end{equation}

\centering
\begin{tikzpicture}[

\end{figure}

\subsubsection{¿Por qué Funciona?}

\begin{enumerate}
    \item \textbf{Flujo de gradiente directo}: El gradiente puede fluir directamente por la skip connection sin atravesar capas no-lineales
    \item \textbf{Aprender identidad es fácil}: Si $F(\mathbf{x}) \approx 0$, entonces $H(\mathbf{x}) \approx \mathbf{x}$
    \item \textbf{Ensemble implícito}: Una ResNet de $n$ bloques tiene $2^n$ caminos posibles (cada skip puede tomarse o no)
\end{enumerate}

    \item $>$100,000 imágenes: ResNet-101, ResNet-152, o arquitecturas más grandes
\end{itemize}

\subsection{DenseNet: Conectividad Densa}

\subsubsection{La Idea: Reutilizar Todo}

Mientras ResNet \textbf{suma} características ($H(x) = F(x) + x$), DenseNet (Huang et al., 2017) las \textbf{concatena}:

\begin{equation}
\mathbf{x}_l = H_l([\mathbf{x}_0, \mathbf{x}_1, ..., \mathbf{x}_{l-1}])
\end{equation}

Donde $[...]$ denota concatenación a lo largo de la dimensión de canales.

\end{figure}

\subsubsection{Growth Rate ($k$)}

El \textbf{growth rate} $k$ es el número de canales que cada capa añade. Si $l_0$ es el número de canales inicial:

\begin{equation}
\text{Canales en capa } l = l_0 + k \times l
\end{equation}

Valores típicos: $k = 12, 24, 32$.

\subsubsection{Transition Layers}

Para evitar que el número de canales crezca demasiado, DenseNet intercala \textbf{transition layers}:

\begin{itemize}
    \item BatchNorm + ReLU + Conv 1×1 (reduce canales a la mitad)
    \item Average Pooling 2×2 (reduce resolución espacial)
\end{itemize}

\subsubsection{Ventajas de DenseNet}

\begin{enumerate}
    \item \textbf{Reutilización de características}: Información de capas tempranas disponible directamente en capas tardías
    \item \textbf{Gradientes fuertes}: Múltiples caminos cortos para el gradiente
    \item \textbf{Eficiencia de parámetros}: Capas estrechas ($k$ pequeño) pero efectivas
    \item \textbf{Excelente en imágenes médicas}: CheXNet (Stanford, 2017) para radiografías usa DenseNet-121
\end{enumerate}

\subsubsection{¿Por qué DenseNet-121?}

\begin{itemize}
    \item 121 capas pero solo \textbf{8 millones de parámetros} (menos que ResNet-18)
    \item Probado exitosamente en múltiples tareas médicas
    \item \textbf{Evidencia empírica:} En nuestros experimentos, DenseNet-121 (59.0\%) superó claramente a DenseNet-161 (54.0\%), confirmando que el aumento de profundidad es contraproducente con este tamaño de dataset.
\end{itemize}

\subsection{YOLO para Clasificación}

\subsubsection{De Detector a Clasificador}

YOLO (\textit{You Only Look Once}) es famoso como detector de objetos. Sin embargo, Ultralytics ofrece versiones específicas para \textbf{clasificación} (sufijo \texttt{-cls}):

\begin{itemize}
    \item Mantienen el backbone convolucional potente
    \item Reemplazan las cabezas de detección por clasificación global
    \item Incluyen pipeline de entrenamiento optimizado
\end{itemize}

\subsubsection{¿Por qué incluir YOLO en el ensemble?}

\begin{enumerate}
    \item \textbf{Arquitectura diferente}: No es ni ResNet ni DenseNet, aporta diversidad
    \item \textbf{Técnicas modernas}: CSP (Cross Stage Partial), SPPF, etc.
    \item \textbf{Pipeline integrado}: Data augmentation, warmup, EMA, etc.
    \item \textbf{Estado del arte}: YOLO26x incorpora avances de 2024-2025
\end{enumerate}

\section{Transfer Learning en Profundidad}

\subsection{El Problema de los Datos Limitados}

Entrenar una CNN desde cero requiere:
\begin{itemize}
    \item \textbf{Muchos datos}: Cientos de miles de imágenes
    \item \textbf{Mucho tiempo}: Días o semanas de entrenamiento
    \item \textbf{Mucho cómputo}: GPUs potentes
\end{itemize}

Con 500 imágenes, una CNN entrenada desde cero:
\begin{enumerate}
    \item Memorizará el conjunto de entrenamiento
    \item Tendrá error de validación muy alto
    \item Aprenderá características de bajo nivel pero no de alto nivel
\end{enumerate}

\subsection{La Solución: Pesos Preentrenados}

\subsubsection{¿Qué aprenden las CNNs?}

Las diferentes capas de una CNN aprenden características de distinta abstracción:

\subsubsection{¿Por qué ImageNet?}

ImageNet es un dataset de 1.4 millones de imágenes en 1000 categorías. Los modelos preentrenados en ImageNet han aprendido características visuales robustas que son útiles para \textbf{cualquier} tarea de visión, incluyendo:

\begin{itemize}
    \item Detección de bordes y texturas
    \item Reconocimiento de patrones geométricos
    \item Sensibilidad a cambios de iluminación
    \item Representaciones jerárquicas de complejidad creciente
\end{itemize}

\subsection{Estrategias de Fine-Tuning}

\subsubsection{Estrategia 1: Feature Extraction (Congelar todo)}

\begin{lstlisting}[caption={Feature extraction: solo entrenar la cabeza}]
# Congelar TODAS las capas
for param in model.parameters():
    param.requires_grad = False

# Solo la nueva cabeza es entrenable
model.fc = nn.Linear(512, 6)
# Unicos parametros entrenables: 512 * 6 + 6 = 3,078
\end{lstlisting}

\textbf{Cuándo usar}: Muy pocos datos ($<$100) o el dominio es muy similar a ImageNet.

\subsubsection{Estrategia 2: Fine-Tuning Parcial (Nuestra elección)}

\begin{lstlisting}[caption={Fine-tuning parcial: descongelar últimas capas}]
# Congelar todo
for param in model.parameters():
    param.requires_grad = False

# Descongelar solo las ultimas capas
for param in model.layer4.parameters():  # ResNet
    param.requires_grad = True

# Nueva cabeza
model.fc = nn.Sequential(
    nn.Dropout(0.5),
    nn.Linear(512, 6)
)
\end{lstlisting}

\textbf{Cuándo usar}: Datos moderados (100-10,000) o el dominio es diferente (fotos naturales $\rightarrow$ dermatoscopia).

\subsubsection{Estrategia 3: Fine-Tuning Completo}

\begin{lstlisting}[caption={Fine-tuning completo: todo entrenable}]
# Todo entrenable (no congelar nada)
model.fc = nn.Linear(512, 6)

# Usar learning rate bajo para no destruir pesos
optimizer = optim.Adam(model.parameters(), lr=1e-5)
\end{lstlisting}

\textbf{Cuándo usar}: Muchos datos ($>$10,000) y el dominio es muy diferente.

\subsection{Learning Rates Diferenciales}

Una técnica clave es usar \textbf{learning rates diferentes} para distintas partes de la red:

\begin{equation}
\text{LR}_{\text{preentrenado}} << \text{LR}_{\text{nuevo}}
\end{equation}

\begin{lstlisting}[caption={Learning rates diferenciales en PyTorch}]
optimizer = optim.AdamW([
    # Capas preentrenadas: LR bajo (ajuste fino)
    {'params': model.layer4.parameters(), 'lr': 1e-4},

    # Nueva cabeza: LR alto (aprender desde cero)
    {'params': model.fc.parameters(), 'lr': 1e-3}
], weight_decay=0.01)
\end{lstlisting}

\textbf{Intuición}:
\begin{itemize}
    \item Las capas preentrenadas ya ``saben'' cosas útiles. Un LR alto las destruiría.
    \item La nueva cabeza está inicializada aleatoriamente. Necesita LR alto para aprender rápido.
\end{itemize}

La regularización es crucial para evitar \textbf{overfitting}, especialmente con datasets pequeños.

\subsection{¿Qué es el Overfitting?}

El \textbf{overfitting} ocurre cuando el modelo memoriza el conjunto de entrenamiento en lugar de aprender patrones generalizables:

\subsection{Dropout}

\subsubsection{Funcionamiento}

Durante el entrenamiento, \textbf{Dropout} apaga aleatoriamente una fracción $p$ de las neuronas:

\begin{equation}
\tilde{h}_i = \begin{cases}
0 & \text{con probabilidad } p \\
\frac{h_i}{1-p} & \text{con probabilidad } 1-p
\end{cases}
\end{equation}

El factor $\frac{1}{1-p}$ es la \textbf{inverted dropout scaling}, que mantiene la magnitud esperada constante.

\subsubsection{¿Por qué Funciona?}

\begin{enumerate}
    \item \textbf{Ensemble implícito}: Cada forward pass usa una ``sub-red'' diferente. Es como entrenar $2^n$ modelos.
    \item \textbf{Previene co-adaptación}: Las neuronas no pueden depender excesivamente de otras específicas.
    \item \textbf{Ruido como regularización}: Añade estocasticidad que dificulta la memorización.
\end{enumerate}

\subsection{Weight Decay (Regularización L2)}

\subsubsection{Formulación Matemática}

El \textbf{weight decay} añade una penalización por pesos grandes a la función de pérdida:

\begin{equation}
\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{CE}} + \frac{\lambda}{2} \|\mathbf{w}\|_2^2 = \mathcal{L}_{\text{CE}} + \frac{\lambda}{2} \sum_i w_i^2
\end{equation}

Donde $\lambda$ es el coeficiente de weight decay.

\subsubsection{Efecto en la Actualización}

El gradiente de la pérdida total es:
\begin{equation}
\nabla_{\mathbf{w}} \mathcal{L}_{\text{total}} = \nabla_{\mathbf{w}} \mathcal{L}_{\text{CE}} + \lambda \mathbf{w}
\end{equation}

La actualización de pesos se convierte en:
\begin{equation}
\mathbf{w}_{t+1} = \mathbf{w}_t - \eta (\nabla_{\mathbf{w}} \mathcal{L}_{\text{CE}} + \lambda \mathbf{w}_t) = (1 - \eta\lambda)\mathbf{w}_t - \eta \nabla_{\mathbf{w}} \mathcal{L}_{\text{CE}}
\end{equation}

El término $(1 - \eta\lambda)$ ``encoge'' los pesos hacia cero en cada paso.

\subsubsection{Intuición}

\begin{itemize}
    \item \textbf{Pesos grandes $\rightarrow$ funciones complejas}: Pueden memorizar ruido
    \item \textbf{Pesos pequeños $\rightarrow$ funciones suaves}: Generalizan mejor
    \item \textbf{Navaja de Occam}: Preferimos la solución más simple que explique los datos
\end{itemize}

\subsection{Data Augmentation como Regularización}

El Data Augmentation no solo aumenta artificialmente el dataset, también actúa como \textbf{regularización implícita}:

\begin{itemize}
    \item El modelo nunca ve exactamente la misma imagen dos veces
    \item Aprende invarianzas (rotación, escala, color) en lugar de memorizarlas
    \item Equivalente a suavizar la función de decisión
\end{itemize}

\subsection{Early Stopping}

\textbf{Early stopping} detiene el entrenamiento cuando el val loss empieza a empeorar:

\begin{lstlisting}[caption={Early stopping manual}]
best_val_f1 = 0

\section{Métricas de Evaluación en Detalle}

\subsection{Matriz de Confusión}

La \textbf{matriz de confusión} es la base de todas las métricas de clasificación:

\begin{figure}[H]
\centering
\begin{tikzpicture}
    \matrix[matrix of nodes, nodes={draw, minimum size=1.2cm, anchor=center},

    % Labels

    \node[right=0.5cm of m-3-2, align=left] {\small False Positive\\(Falsa alarma)};

\end{tikzpicture}

\end{figure}

Para multiclase, la matriz es $C \times C$ donde $M_{ij}$ = número de muestras de clase $i$ predichas como clase $j$.

\subsection{Métricas Derivadas}

\subsubsection{Accuracy (Exactitud)}

\begin{equation}
\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN} = \frac{\text{Correctos}}{\text{Total}}
\end{equation}

\begin{warningbox}[Problema del Accuracy con Datos Desbalanceados]
Si el 95\% de las imágenes son benignas, un modelo que siempre prediga ``benigno'' tiene 95\% accuracy pero es \textbf{inútil clínicamente}.
\end{warningbox}

\subsubsection{Precision (Valor Predictivo Positivo)}

\begin{equation}
\text{Precision} = \frac{TP}{TP + FP} = P(\text{Real}=1 | \text{Pred}=1)
\end{equation}

``De todos los que diagnostiqué como melanoma, ¿cuántos realmente lo eran?''

\textbf{Alta precisión} = pocas falsas alarmas = pacientes no preocupados innecesariamente.

\subsubsection{Recall (Sensibilidad)}

\begin{equation}
\text{Recall} = \frac{TP}{TP + FN} = P(\text{Pred}=1 | \text{Real}=1)
\end{equation}

``De todos los melanomas reales, ¿cuántos detecté?''

\textbf{Alto recall} = pocos casos perdidos = melanomas detectados a tiempo.

\subsubsection{F1-Score}

\begin{equation}
\text{F1} = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{2 \cdot TP}{2 \cdot TP + FP + FN}
\end{equation}

El F1 es la \textbf{media armónica} de precision y recall. Es bajo si \textbf{cualquiera} de los dos es bajo.

\subsection{Agregación para Multiclase}

\subsubsection{Macro-Average}

\begin{equation}
\text{F1-Macro} = \frac{1}{C} \sum_{c=1}^{C} \text{F1}_c
\end{equation}

Promedio simple: \textbf{todas las clases pesan igual}, independientemente de su frecuencia.

\textbf{Elegimos F1-Macro} porque:
\begin{itemize}
    \item Da igual importancia a MEL (35 muestras) que a NEV (95 muestras)
    \item Penaliza fuertemente fallar en clases minoritarias
    \item Es el estándar para clasificación desbalanceada
\end{itemize}

\subsubsection{Weighted-Average}

\begin{equation}
\text{F1-Weighted} = \sum_{c=1}^{C} \frac{n_c}{N} \cdot \text{F1}_c
\end{equation}

Pondera por la frecuencia de cada clase. Menos sensible a clases minoritarias.

\subsubsection{Micro-Average}

\begin{equation}
\text{F1-Micro} = \frac{2 \cdot \sum_c TP_c}{2 \cdot \sum_c TP_c + \sum_c FP_c + \sum_c FN_c}
\end{equation}

Agrega todos los TP, FP, FN globalmente. Equivale al accuracy en multiclase.

\subsection{Cohen's Kappa}

El \textbf{coeficiente Kappa} mide el acuerdo corrigiendo por el azar:

\begin{equation}
\kappa = \frac{p_o - p_e}{1 - p_e}
\end{equation}

Donde:
\begin{itemize}
    \item $p_o$ = proporción de acuerdos observados (accuracy)
    \item $p_e$ = proporción de acuerdos esperados por azar
\end{itemize}

\begin{lstlisting}[caption={Cálculo de métricas en Python}]
from sklearn.metrics import (
    classification_report,
    confusion_matrix,
    f1_score,
    cohen_kappa_score
)

\subsection{Función de Entrenamiento Completa}

\begin{lstlisting}[caption={Loop de entrenamiento con todas las mejoras}]
import copy
import torch
import torch.nn as nn
from sklearn.metrics import f1_score

def entrenar_modelo(model, train_loader, val_loader, criterion,
                    optimizer, device, epochs=25,
                    nombre_archivo="mejor_modelo.pth"):
    """
    Entrena un modelo con:
    - Guardado del mejor modelo (por F1-Macro)
    - Tracking de historial
    - Evaluacion en validacion cada epoca
    """
    print(f"Iniciando entrenamiento por {epochs} epocas...")

    historial = {
        'train_loss': [],
        'val_loss': [],
        'val_f1': []
    }

    best_f1 = 0.0
    best_model_wts = copy.deepcopy(model.state_dict())

    for epoch in range(epochs):
        # ========== FASE DE ENTRENAMIENTO ==========
        model.train()  # Modo entrenamiento (Dropout activo)
        running_loss = 0.0

        for inputs, labels in train_loader:
            # Mover a GPU
            inputs = inputs.to(device)
            labels = labels.to(device)

            # Forward pass
            optimizer.zero_grad()
            outputs = model(inputs)
            loss = criterion(outputs, labels)

            # Backward pass
            loss.backward()
            optimizer.step()

            running_loss += loss.item() * inputs.size(0)

        epoch_train_loss = running_loss / len(train_loader.dataset)

        # ========== FASE DE VALIDACION ==========
        model.eval()  # Modo evaluacion (Dropout desactivado)
        val_loss = 0.0
        y_true = []
        y_pred = []

        with torch.no_grad():  # No calcular gradientes
            for inputs, labels in val_loader:
                inputs = inputs.to(device)
                labels = labels.to(device)

                outputs = model(inputs)
                loss = criterion(outputs, labels)
                val_loss += loss.item() * inputs.size(0)

                _, preds = torch.max(outputs, 1)
                y_true.extend(labels.cpu().numpy())
                y_pred.extend(preds.cpu().numpy())

        epoch_val_loss = val_loss / len(val_loader.dataset)
        epoch_val_f1 = f1_score(y_true, y_pred, average='macro')

        # Guardar en historial
        historial['train_loss'].append(epoch_train_loss)
        historial['val_loss'].append(epoch_val_loss)
        historial['val_f1'].append(epoch_val_f1)

        # Mensaje de progreso
        print(f"Ep {epoch+1}/{epochs} | "
              f"Train Loss: {epoch_train_loss:.3f} | "
              f"Val Loss: {epoch_val_loss:.3f} | "
              f"Val F1: {epoch_val_f1:.4f}", end="")

        # ========== GUARDAR MEJOR MODELO ==========
        if epoch_val_f1 > best_f1:
            best_f1 = epoch_val_f1
            best_model_wts = copy.deepcopy(model.state_dict())
            torch.save(model.state_dict(), nombre_archivo)
            print(" [MEJOR] Guardado.")
        else:
            print("")

    print(f"\nFin. Mejor F1 en Validacion: {best_f1:.4f}")

    # Restaurar los MEJORES pesos (no los ultimos)
    model.load_state_dict(best_model_wts)
    return model, historial
\end{lstlisting}

\section{Construcción del Ensemble}

\begin{lstlisting}[caption={Implementación completa del ensemble}]
import torch
import torch.nn.functional as F
import numpy as np
from PIL import Image
from torchvision import transforms

def crear_ensemble(rutas_modelos, ruta_test, device):
    """
    Crea un ensemble de modelos y evalua en test.

    Pesos del ensemble:
    - YOLO26x: 60% (mejor modelo individual)
    - DenseNet: 20%
    - ResNet: 20%
    """

    # 1. Cargar modelos PyTorch
    def cargar_resnet(path, num_classes):
        model = models.resnet18(weights=None)
        model.fc = nn.Sequential(
            nn.Dropout(0.5),
            nn.Linear(512, num_classes)
        )
        model.load_state_dict(torch.load(path, map_location=device))
        model.to(device)
        model.eval()
        return model

    def cargar_densenet(path, num_classes):
        model = models.densenet121(weights=None)
        model.classifier = nn.Sequential(
            nn.Dropout(0.5),
            nn.Linear(1024, num_classes)
        )
        model.load_state_dict(torch.load(path, map_location=device))
        model.to(device)
        model.eval()
        return model

    model_resnet = cargar_resnet(rutas_modelos['resnet'], 6)
    model_densenet = cargar_densenet(rutas_modelos['densenet'], 6)
    model_yolo = YOLO(rutas_modelos['yolo'])

    # 2. Preprocesamiento
    transform = transforms.Compose([
        transforms.Resize((224, 224)),
        transforms.ToTensor(),
        transforms.Normalize([0.485, 0.456, 0.406],
                           [0.229, 0.224, 0.225])
    ])

    # 3. Inferencia
    y_true = []
    y_pred = []
    clases = sorted(os.listdir(ruta_test))

    for idx_clase, nombre_clase in enumerate(clases):
        ruta_clase = os.path.join(ruta_test, nombre_clase)
        imagenes = [f for f in os.listdir(ruta_clase)
                   if f.endswith(('.jpg', '.png'))]

        for img_name in imagenes:
            img_path = os.path.join(ruta_clase, img_name)

            # Prediccion PyTorch
            img = Image.open(img_path).convert('RGB')
            img_tensor = transform(img).unsqueeze(0).to(device)

            with torch.no_grad():
                probs_res = F.softmax(model_resnet(img_tensor), dim=1)
                probs_dense = F.softmax(model_densenet(img_tensor), dim=1)

            probs_res = probs_res.cpu().numpy()[0]
            probs_dense = probs_dense.cpu().numpy()[0]

            # Prediccion YOLO
            result = model_yolo(img_path, verbose=False)[0]
            probs_yolo = np.zeros(6)
            for i, conf in enumerate(result.probs.data.cpu().numpy()):
                nombre = result.names[i]
                if nombre in clases:
                    probs_yolo[clases.index(nombre)] = conf

            # FUSION: Promedio ponderado
            probs_final = (
                0.20 * probs_res +
                0.20 * probs_dense +
                0.60 * probs_yolo
            )

            pred = np.argmax(probs_final)

            y_true.append(idx_clase)
            y_pred.append(pred)

    return y_true, y_pred, clases
\end{lstlisting}

\section{Análisis y Discusión}

\subsection{¿Por qué YOLO26x es el mejor modelo individual?}

\begin{enumerate}
    \item \textbf{Arquitectura moderna}: Incorpora técnicas de 2024-2025 como CSPNet, SPPF, y attention mechanisms
    \item \textbf{Pipeline optimizado}: Data augmentation avanzado, warmup, EMA (Exponential Moving Average)
    \item \textbf{Mayor capacidad}: $\approx$90M de parámetros vs 11.7M de ResNet-18
\end{enumerate}

\subsection{¿Por qué el Ensemble mejora?}

El ensemble combina modelos con \textbf{errores diferentes}:

\begin{itemize}
    \item \textbf{YOLO26x}: Muy bueno en MEL y SEK, pero confunde ACK/SCC
    \item \textbf{ResNet-18}: Balance razonable, mejor en NEV
    \item \textbf{DenseNet-121}: Captura características diferentes por su arquitectura densa
\end{itemize}

Al promediar, los errores individuales tienden a cancelarse.

\subsection{Limitaciones}

\begin{enumerate}
    \item \textbf{Dataset pequeño}: 500 imágenes de entrenamiento limitan la capacidad de generalización
    \item \textbf{Desbalanceo en MEL}: Solo $\approx$35 imágenes de melanoma dificultan el aprendizaje
    \item \textbf{Overfitting}: A pesar de la regularización, se observa divergencia train/val
    \item \textbf{Recall de MEL}: 55\% significa que perdemos 45\% de los melanomas (5/11)
\end{enumerate}
